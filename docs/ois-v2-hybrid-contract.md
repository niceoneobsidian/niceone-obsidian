# OIS v2 Hybrid — Canonical Environment Contract\n\n## Purpose\n\nThe repository now treats `.env.example` as the **canonical OIS v2 Hybrid runtime contract**.\n\nThe contract combines the existing OIS governance architecture with stronger transport, authentication, OAuth, retry, connection-pool, observability, and production-safety primitives.\n\n## Authority model\n\n| Concern | Authoritative layer |\n| --- | --- |\n| Runtime defaults | `.env.example` / runtime environment |\n| Provider identity | Provider/source registry |\n| Adapter implementation | Adapter registry |\n| Capability identity | Capability registry |\n| Tool identity | Tool registry |\n| Authorization | Policy engine |\n| Credentials | Credential resolver / deployment secret manager |\n| Tenant isolation | Tenant scope + PostgreSQL RLS / policy |\n| Execution | OIS Kernel / control plane |\n| Evidence | Evidence ledger/store |\n| Provenance | Provenance records |\n| Trust | Conformance suites |\n| Live testing | Explicit protected live profile |\n\nA variable such as `GITHUB_ENABLED=true` can expose configuration, but cannot authorize an unregistered tool, bypass policy, materialize an out-of-scope credential, or bypass tenant isolation.\n\n## Safe canonical profile\n\nThe committed `.env.example` is intentionally offline-first:\n\n- external calls disabled;\n- writes/deletes/publishing disabled;\n- live conformance disabled;\n- GitHub disabled;\n- credential resolution fail-closed;\n- policy fail-closed;\n- tenant isolation enabled;\n- negative/security conformance enabled;\n- evidence/provenance enabled.\n\nLive testing belongs in a protected `.env.live` or CI environment and must never be represented as the canonical example.\n\n## Repository reality alignment\n\nThe first live source is aligned to the connector that actually exists in the repository:\n\n`github.rest.user`\n\nThis is deliberate. The environment contract does not invent a `repository.read` capability that the current connector has not established.\n\nThe repository currently contains:\n\n- `CredentialResolver` and `TenantScope`;\n- `SourceAdapterRegistry`;\n- GitHub source integration;\n- Kernel `PolicyEngine`;\n- canonical `ToolRegistry`;\n- PostgreSQL tenant/RLS conformance;\n- protected Phase A live integration tests;\n- phase-gate configuration;\n- P0 conformance CI.\n\n## Validation\n\nRun:\n\n```bash\npython scripts/validate_ois_v2_hybrid.py\npython -m pytest -q tests/conformance/test_ois_v2_hybrid_contract.py\n```\n\nThe validator checks:\n\n1. canonical contract presence;\n2. required safety variables;\n3. safe default values;\n4. absence of populated secrets;\n5. actual registry/adapter/policy/credential implementation anchors;\n6. tenant-isolation and live-test anchors;\n7. phase-gate anchors.\n\n## Evidence status\n\nThe validator is a **contract-integrity gate**, not a production-readiness certificate.\n\nThe following distinction remains mandatory:\n\n```text\nDECLARED\n   ↓\nIMPLEMENTED\n   ↓\nTESTED\n   ↓\nINTEGRATED\n   ↓\nDEPLOYED\n   ↓\nACTIVATED\n   ↓\nPRODUCTION VERIFIED\n```\n\nPassing this validator means the canonical environment contract is internally safe and anchored to repository structures. It does not claim that every provider, transport, security scenario, live API, CI gate, or production deployment represented by the contract is already implemented or verified.\n\n## Next conformance boundary\n\nThe remaining work is evidence closure:\n\n1. map every declared integration to a concrete provider/source/adapter/capability/tool;\n2. map every credential path to `CredentialRef -> CredentialResolver -> Authenticator`;\n3. map every policy declaration to executable authorization tests;\n4. map tenant controls to adversarial isolation tests;\n5. map observability declarations to trace/metric/log assertions;\n6. map live-provider declarations to protected read-only E2E tests;\n7. map production declarations to deployment, rollback, and runtime evidence.\n\nOnly those mappings should move a declaration from architectural intent to verified capability.
